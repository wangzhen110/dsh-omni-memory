# 全维度成熟度评估：够不够完善？

评估日期：2026-11-21
被评版本：3.8.0（提交 `ed5f1d7`）
方法：源码逐维度核实 + 端到端实测 + GitHub 竞品对标（一手 README + API 验证，见 `REVIEW-2026-11-21.md`）
性质：只读评估，未修改源码

---

## 一句话结论

**分水岭很明显：工程维度已经完善，甚至领先；但"记忆智能"维度还有明确代差。**

如果用户问的是"这东西稳不稳、安全不安全、数据会不会丢、能不能接进我的工具"——**够了，可以放心用**。
如果用户问的是"它能不能像 mem0/claude-mem 那样自己把记忆长出来、越用越准"——**还不够，这是下一阶段的事**。

用一句话概括：**它是一个极其可靠的"记忆数据库 + 检索内核"，但还不是一个"会自己成长的记忆系统"。**

## 与竞品的相对位置

### 我们领先或持平的（5 项工程能力）

1. **零依赖、单文件、默认离线**——mem0 要 LLM+embedding 服务，claude-mem 要 Bun+uv+Chroma+observer，Graphiti 要自备图库+LLM，我们是 `node:sqlite` 内置 + 单 `omni.db` 复制即备份。
2. **全量审计可回滚**——墓碑、`valid_to`、`superseded_by`、`dream_rollback`、`restore`，多数竞品默认检索即隐藏历史。
3. **确定性做梦校验**——不调模型、只标记不改写、commit 才替代、可一键回滚；竞品 observer 直接写入无中间态。
4. **项目分层强隔离**——`proj:*` 键 + 双向 scope 防线，dna-memory 无隔离语义、mem0 用 user_id 而非工作区。
5. **故障经验闭环**——`problemKey` + `solutionStatus` + `evidence` + `reuseCount`，竞品普遍只有通用记忆，没有结构化排障记忆。

### 我们落后的（3 项记忆智能）

1. **记忆自己长出来**（代差）——mem0 ADD-only 抽取、claude-mem observer。我们是"人写库"。
2. **token 渐进披露**——claude-mem 注入 compact index（50-100 token/条）按需拉全文（约 1/10 token）。我们虽有 `memory_get`，但画像仍是一次性 1200 字全文。
3. **巩固与遗忘**——mcp-memory-service 自主巩固（聚类/压缩/关联/受控遗忘）+ insight cards。我们 compact 只按时间墓碑化，dream 只标记不抽象。

## 关键判断："完善"要分场景

| 使用场景 | 是否够用 | 说明 |
|---|---|---|
| 个人开发者跨会话记住项目约定、踩坑、决策 | ✅ 够用且好用 | 这正是设计目标，故障经验库是独有优势 |
| 多项目/多 agent 共享一份记忆，要求不串味 | ✅ 够用 | 项目分层 + scope 双向防线已实测可靠 |
| 大库（万级以上）低延迟检索 | ✅ 够用 | 有界采样 p95 2.4ms；但代价是极旧且无词面命中的记忆可能召回不到 |
| 要求"装上就不用管、记忆自动生成" | ❌ 不够 | 仍需模型自觉 `memory_write`，长对话易漏写 |
| 要求"越用越准、自动纠错巩固" | ❌ 不够 | 反馈闭环已建但巩固/重排未做 |
| 团队/云端/多端同步 | ⛔ 设计外 | 纯本地 loopback 是明确取舍，非缺陷 |

## 如果要从"完善"走向"完美"，优先级

> 前提：守住三条底线——自动抽取/模型调用一律 opt-in、不引重型依赖、不改"只增不改 + 可回滚"。

1. **会话自动捕获**（P0，最高性价比）——把拉取式 packet 升级为 hook 驱动的自动注入 + 从 transcript 抽取候选 note（进待确认队列，不直接入库）。这是"能力脱离 DSH"的最后一块，也是从"人写库"到"库自己长"的第一步。
2. **检索重排 + 语义向量**（P1）——top-20 可插拔 rerank，配合 golden 门禁量化收益；语义 embedding 做成 opt-in 端点。
3. **巩固 / 分层摘要**（P1）——把同实体/同 problemKey 的活跃笔记浓缩成带来源链的摘要，旧的置 `superseded_by`；画像改为"全局摘要 + 项目摘要 + 命中详情"三层，缓解 1200 字瓶颈。
4. **渐进拆 core**（基础设施）——`index.js` 已 5258 行，retrieval/store 边界最清晰，先抽这两个；配合导出符号快照测试防止假绿。
