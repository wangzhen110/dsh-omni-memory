## 二、P0 严重问题

### P0-1 `POST /mcp` 无回环校验，非回环绑定 = 无鉴权全域工具接口
- **维度**：安全 / 协议／**已交叉验证**（安全、协议两路独立发现）
- **位置**：`hosts/http/server.mjs:223-230`、`57-66`
- **证据**：13 条 REST 路由逐条有 `isLoopback`（如 `index.js:4056`），唯独权限最大的 `/mcp` 只有 `mcpMutationAllowed`（CSRF），没有回环门禁：`if (req.method === 'POST' && !mcpMutationAllowed(req)) 403; await serveMcp(req, res);`。而 `mcpMutationAllowed` 对无 Origin 的客户端只要 `Content-Type: application/json` 就放行。
- **触发**：`omni serve --bind 0.0.0.0`（CLI 明确支持，`hosts/cli.mjs:284`）。局域网任意主机 `curl -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"memory_export"}}' http://<ip>:7788/mcp`。
- **影响**：19 个工具无凭据可用，含全库原文读取、`memory_export`（可写任意路径，见 P3-3）、`memory_import`（可读任意本地文件入库）、遗忘 / 改写记忆。`/health`（:212）另泄露 project/sessionId。
- **修复**：在 `createServer` 入口对**所有**请求统一做一次 `isLoopback` 门禁（提取 `index.js` 的实现到 `hosts/shared` 共用）；若产品确需跨机，强制显式开关 + 进程凭据，不依赖默认 bind。
- **注**：保持默认 `127.0.0.1` 时此项不成立——但文档承诺的防线在 `--bind` 一改即全线失效。

### P0-2 `applyManagedBlock` 遇孤立 start 标记静默删除用户手写内容
- **维度**：数据丢失 / 健壮性／**已交叉验证**
- **位置**：`hosts/shared/rules.mjs:89-103`
- **证据**：正则 `<!-- MARK v\d+ start -->[\s\S]*?<!-- MARK v\d+ end -->` 只匹配成对标记；无匹配时直接追加完整新块。若规则文件因手改 / 中断只有 start 无 end：第 1 次追加后出现两个 start、一个 end；第 2 次非贪婪匹配从**第一个** start 吞到新块 end，把中间用户内容一并 `replace` 掉。
- **触发**：`omni rules --write` 挂在 SessionStart 钩子上反复执行（README 推荐用法）。
- **影响**：静默删除用户在 CLAUDE.md / AGENTS.md 手写的段落，且无备份、无提示。这是本项目"只增不改"价值观的反面。
- **修复**：写前统计 start/end 数量，不配对则 fail-closed（报错或跳过，不追加）；用严格锚点只替换成对块；多块显式清理。

## 三、P1 高危问题

### P1-1 `contested` 事实未排除，进入常驻画像与 persona 提炼链
- **维度**：安全 / 隐私／**已交叉验证**
- **位置**：`index.js:2481-2493`（profileFactLines）、`:2582-2587`（personaEvidence）、`:2826`、`:4638-4641`
- **证据**：notes 路径正确写了 `contested = 0`（`:2805`、`:3757`），但 `profileFactLines` 的事实查询只有 `deleted_at IS NULL AND valid_to IS NULL`，无 contested 过滤；`facts` 表确有 `contested` 列（`:411`），导入会原样写入（`:1280`）。
- **影响**：违反 `THREAT-MODEL.md:39`「contested 不注入」的既定控制。争议 / 恶意事实绕过审核进入每轮系统提示，还可能被提炼为「高于临时指令」的 persona（`:2776`）。
- **修复**：两处事实查询加 `AND contested = 0`；画像 body 注入前再做一次结构化过滤。

### P1-2 `migrate()` 在维护租约之外执行，违反 ADR-028
- **维度**：数据一致性 / 并发／**已交叉验证**
- **位置**：`index.js:469-498`，尤其 `:475`（`migrate(db)` 在 `if (lease)` 外）
- **证据**：v4 迁移物理清空向量 `DELETE FROM vectors`（`:554-556`）。两进程同时首次打开旧库：A 拿租约迁移+回填并写 `vector_backfill_version`；B 启动时也跑 `migrate()` 重放 v4 清空向量，但 B 不在租约内不会回填，标记已存在 → 下次启动判定无需回填。
- **影响**：低频但真实——多进程 + 旧库升级 + 回填耗时窗口下，向量召回整路静默失效且不自愈。
- **修复**：把 `migrate(db)` 移入 `if (lease)` 块内。

### P1-3 维护租约「旧持有者释放」竞态
- **维度**：并发／安全审计发现
- **位置**：`index.js:1072`（`releaseLease` 无条件 `DELETE FROM meta WHERE key = ?`）
- **影响**：维护 / dream 执行超过 TTL 后旧持有者会删掉新持有者的租约，导致任务被多进程重复执行。
- **修复**：条件删除 `DELETE ... WHERE key=? AND value=?`，传入获取时写入的到期值。

### P1-4 JSON-RPC `id: null` 被当作通知，`ping` 永久挂起
- **维度**：协议合规／**已交叉验证**
- **位置**：`hosts/mcp/server.mjs:75`、`:97-98` 对比 `:100-107`
- **证据**：`const isRequest = id !== undefined && id !== null;` —— 规范中通知的判定是**缺少 id 成员**，`id:null` 是合法请求。结果：`{"id":null,"method":"ping"}` 无响应，`tools/list` 同 id 却响应，行为不一致。
- **修复**：用 `hasOwnProperty(message,'id') && id !== undefined` 判定。

### P1-5 发给「请求型方法」的通知产生无 id 非法响应帧
- **维度**：协议合规／已交叉验证
- **位置**：`hosts/mcp/server.mjs:81`、`:101`、`:132`、`:181`
- **证据**：`initialize` / `tools/list` / `prompts/get` 直接 `okResult(id, …)` 不检查 `isRequest`；`dispatch` 中 `if (reply) write(...)`，通知场景 `id` 为 undefined 被 JSON.stringify 省略，stdout 输出无 id 的响应。
- **影响**：严格客户端报错，污染 stdio 协议流；违反「禁止对通知回复」。
- **修复**：所有 `okResult` 分支统一 `isRequest ? okResult(...) : null`。

### P1-6 前端 `scope=project` 伪层级导致搜索与星图详情永久失效
- **维度**：功能性／**已交叉验证**
- **位置**：`index.js:4305-4306`（`/node`）、`:4520`（`/search`）对比 `:4073-4074`（`/list` 特判 project）
- **证据**：`/list` 对 `scope==='project'` 特判为 `scope LIKE 'proj:%'`；`/search` 与 `/node` 把它当字面 scope 传入 `scopeClause`。前端 `client.js:343/477`、`app.js:100`、`index.html:29` 都会传 `project`。
- **影响**：选「项目」后搜索恒返回空、星图点选恒显示「不可读取」，列表却正常——用户误以为记忆丢失。
- **修复**：`/search`、`/node` 复用 `/list` 的伪层级解析。

## 四、P2 中危问题（择要）

### 数据与导入
- **P2-1** `index.js:1265-1271`：导入时代替笔记被去重后，`superseded_by` 回退为源库原始 id，产生悬空指针，旧笔记被永久隐藏且不可恢复。
- **P2-2** `index.js:1272-1288`：导入 facts 不先失效同层同 `(subject,relation)` 活动行，破坏 INV-02，画像出现两个「当前值」。
- **P2-3** `index.js:1172`：审计备份（含被替代笔记）重复导入不去重，往返不幂等。
- **P2-4** `index.js:1474-1483`：LIKE 检索未转义 `%` / `_`，通配符放大候选集；`queryTerms` 与 `tokenize` 对 `_` 的分词语义不一致。
- **P2-5** `index.js:3955`：`keepChunks=0` 被钳为 5000 而非文档下限 50，传 10 反得 50，行为不连续。

### 协议与传输
- **P2-6** `hosts/http/server.mjs:172-189`：空 batch `[]` 返回 202，规范要求 `-32600`；batch 内元素为数组时静默丢弃。
- **P2-7** `hosts/mcp/server.mjs:73-77`：缺 `jsonrpc:"2.0"` 版本校验，非规范请求被正常处理。
- **P2-8** `hosts/mcp/server.mjs:177`：stdout 无 EPIPE 处理，客户端提前断开（如 `| head -1`）导致服务进程崩溃。
- **P2-9** `hosts/shared/rules.mjs:16-51` vs `bin.mjs:43-49`、`http/server.mjs:114`：`initialize.instructions` 是两处手写摘要且内容不同，不是 `RULES_TEXT`，违反「五通道同一份规则」承诺。

### 写侧隔离
- **P2-10** `index.js:3466-3479`、`:1080-1097` 等：`solution_report` / `forget` / `restore` / `dream_replace` 按 id 定位，无 scope 归属校验。读侧隔离完善、写侧无隔离；拿到别项目 id 即可跨项目改写。

### 前端
- **P2-11** `client.js:463-472`、`:377-386`、`:421-444`：写操作（遗忘 / 反替代 / 保存 persona）不检查 `response.ok` 与 `body.ok`，失败静默刷新；全项目无二次确认弹窗。
- **P2-12** `client.js:318-358`、`:474-486`、`star-map.html:1115-1192`：fetch 无请求序号 / `alive` 守卫，快速切换时旧响应覆盖新状态，详情查询 scope 错配。
- **P2-13** `docs/CHANGELOG.md:23-27`、`ADR/016`  vs `star-map.html:271,287`：文档声称「移植 Canvas 2D、4 旋臂、12000 星、16px 拾取、>34ms 降质」，实测是内嵌 THREE 的 **WebGLRenderer、6 旋臂、约 49 万点**（`MAIN=350000/FIELD=100000/CORE=13000/BAR=26000`）、21px 拾取、无自适应降质。技术栈根本性不符。
- **P2-14** `hosts/http/web/star-map.html`：主线程一次性同步生成约 50 万点，无 LOD / 帧耗时降级；约 4.8 万点隐藏几何体（`gasField/haze/nebulaPlane/dustPlane/barGlow` 设 `visible=false` 后从未启用）仍构建并上传 GPU。

### 文档核心矛盾
- **P2-15** `docs/DESIGN.md:390` 写 `OMNI_SCOPE_JUDGE` 默认 `always`，`:531`、README、REFERENCE、源码（`:225`）都是 `off`。这是隐私承诺的核心开关，隐私默认值以 `off` 为准。
- **P2-16** `docs/DESIGN.md:438` 的 D-01 仍列「真语义召回缺失」，但 CHANGELOG 1.2.0 称 D-01~D-11 全关闭、FR-21 已实现。

- **P2-18** `docs/DESIGN.md:149,158` 称 `index.js ~2561 行 / client.js ~1108 行`，实测 4700 / 1500，漂移近一倍。

## 六、明确「未发现」的类别（重要，避免过度整改）

- **SQL 注入**：未发现。所有外部输入经 `?` 占位符；`${}` 拼接的是代码常量、表名白名单或参数化片段。
- **scope 读侧绕过**：未发现。FTS / 向量 / bigram / graph / node / list / timeline / profile 的「SQL 过滤 + JS 复核」两道防线完整（`scopeAllows` 语义一致），ADR-020 落实到位。
- **XSS / 前端注入**：未发现。全前端零 `innerHTML` / `eval` / `dangerouslySetInnerHTML`，正文走 React children 或 `textContent`；恶意笔记只能作为纯文本显示。
- **重定向 / 代理头伪造**：`isLoopback` 只读 `socket.remoteAddress`，不信任 `X-Forwarded-For`，IPv4/IPv6/映射地址覆盖。
- **命令注入**：CLI 全程无 `child_process`，无注入面。
- **假通过测试**：未发现。`ok:true` 断言均伴随内容断言，dry-run 有查库确认，无 `test.skip` / 顺序依赖。
- **原型污染 / ReDoS / 定时器泄漏**：未发现可控利用。
- **第二套写入路径**：核实为假——三入口复用同一工具注册表，`REFERENCE` 的说法成立。

## 八、修复路线图

**第一批（阻断级，建议立即）**
1. P0-1 `/mcp` 统一回环门禁
2. P0-2 `applyManagedBlock` 标记配对 fail-closed
3. P1-1 contested 事实过滤
