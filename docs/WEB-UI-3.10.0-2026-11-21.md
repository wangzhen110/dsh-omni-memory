# 3.10.0 记忆概览仪表盘

> 2026-11-21 · 真实库接入 · 默认 `/` 入口

## 这次改了什么

旧网页是「记忆列表 / 星图 / 规则」三块工具面板，能用，但回答不了“我到底记住了什么、准不准、最近在做什么、哪些该处理”。3.10.0 把默认 `/` 改为**记忆概览**，旧列表迁移到 `/panel.html`。

首屏先给一句结论、5 个 KPI 和 7 个面板：

- 一句话：记住了多少条，其中多少条可以直接调用。
- 5 个 KPI：活跃记忆、活跃项目、待处理、召回有用率、知识连接。
- 记忆增长：每周新增堆叠柱 + 累积曲线，可切 4 / 6 / 12 周。
- 记忆健康：有效 / 有争议 / 待验证 / 已失效的环图与处理队列。
- 项目分布：全局层与项目层分开统计的横向条形。
- 活跃日历：最近 84 天，每天写入多少条。
- 项目活跃带：项目首次与最近写入的真实时间区间。
- 知识连接：事实主谓宾的迷你关系图。
- 关于你：显式画像优先；画像为空时只展示可回原文的偏好信号。
- 最近动态：真实笔记、事实、候选的最近写入。

同日在一台新的 Windows 机器上复测（`C:\Users\64627\.dsh\memory\omni.db`）：活跃笔记 28 条、活跃事实 6 条、chunks 889 个、3 个 scope、1 条过期事实、0 条召回反馈、1 条显式画像。这个库暴露了一个关键口径错误：第一版把 chunks 也算进了增长柱、累积曲线、日历和项目条形，页面出现「28 条活跃记忆却新增 923 条」「4 个项目层都有数据」的错位；修正后增长与日历只计 notes + facts，chunks 只作为存储量展示，项目记忆量也只算 notes + facts，另有「仅转写」项目行单独标注。真实页面因此显示 28 条笔记 + 6 条事实、健康分 97、1 个有记忆项目层 + 2 个仅转写项目层。

因此页面必须处理四类“空”：

1. persona 为空 → 「画像表为空」+ 原始偏好信号，不生成推断结论。
2. chunks / 候选为 0 → 图表显示 0，不编造会话数。
3. 召回反馈为 0 → 「暂无反馈」，不显示百分比。
4. 只有两天写入 → 日历与增长图显示空白天数，不补随机数据。

## 图表口径

- **记忆增长**：堆叠柱是每周新增的 notes / facts；白色曲线是窗口起点前基线累加后的总量。会话块（chunks）只作存储量，不进柱子也不进累积曲线——一个 28 条笔记的库可能有 889 个 chunks，混在一起会让增长图失真。
- **记忆健康**：环图按 有效 / 有争议 / 待验证 / 已失效 的占比着色；分数 = 有效 / 总口径。分母包含已失效项，否则过期事实会被藏起来。
- **项目分布**：全局与项目层必须同时出现，否则 1,235 条里 1,215 条看起来“消失”。全局行单独按 100% 画；项目层条形以项目层最大记忆量为基准，让 20 条的项目也能看清，右侧数字是 notes + facts 的真实记忆量。只有 chunks、没有 notes/facts 的项目显示「仅转写」，不进入活跃项目数。
- **活跃日历**：固定 84 格，按周日起列；颜色按当日 notes + facts 写入量分 0–4 级；峰值与空白天数直接写在图下。
- **项目活跃带**：用 `firstAt` / `lastAt` 画区间。数据只有几天时自动收窄到 30 天窗口，避免 84 天里只剩一个小点；图上明确写「活动区间，不是任务甘特」。条的标签优先写记忆条数，只有转写的项目写「仅转写 N 块」。
- **知识连接**：只画 active facts 的主谓宾和边数统计；不把 1,235 条笔记硬塞进迷你图。完整图走星图页。
- **画像**：显式 key/value 优先；为空时显示 `profile.signals`（全局偏好笔记最近 5 条），每条带 source、时间和笔记 id，可回原文。

## 为什么没有 3D 圆柱 / 真甘特

- **3D 圆柱**：透视会扭曲高度比较，且遮挡标签；概览要的是快速比较，所以用 2D 胶囊条形和堆叠柱。3D 只适合展示，不适合读数。
- **真甘特**：当前 schema 没有 `tasks`、`start_at`、`due_at`、`status`、`depends_on`，只有笔记时间戳。用笔记时间戳画“任务条”是伪造项目计划，所以只做项目活跃带；等任务模型落地后再加真甘特。

## 接口

`GET /omni-memory/overview?range=12w&scope=all`

- 仅 loopback，非 loopback 403。
- `range`: `4w` / `6w` / `12w` / `26w`，默认 `12w`。
- `scope`: `all` / `global` / `project` / 精确项目键，默认 `all`。
- 返回：`stats`、`health`、`series`、`daily`、`projects`、`profile`、`activity`、`graph`。
- 统计口径：活跃 notes 排除 deleted 与 superseded；活跃 facts 排除 deleted 与 `valid_to` 非空；`pending = contested + pendingCandidates + invalid`；`usefulRate` 在 `recallTotal=0` 时为 `null`。增长序列、84 天日历只统计 notes + facts。
- `projects` 始终包含 global；`projectRows` 带 `memory = notes + facts` 与 `status`（active / watch / quiet / transcript），按 memory 排序；`projectActive` 只数有 notes/facts 的非 global 项目，`transcriptProjects` 单独数只有 chunks 的项目。
