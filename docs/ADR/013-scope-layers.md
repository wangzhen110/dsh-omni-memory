# ADR-013：记忆分「项目级 / 全局级」两层

- 日期：2026-11-14
- 状态：已采纳

## 背景

`scope` 字段早已存在，但只被当作"检索过滤参数"：

- 常驻画像**不看 scope**，任何项目笔记都会出现在所有对话里；
- 转录层捕获时**不写 scope**；
- 检索过滤只做精确匹配，项目查询看不到全局层；
- 界面没有分层视图。

结果就是"有字段、没分层"——项目细节会污染其他会话。

## 决策

### 两层定义

| 层 | 取值 | 语义 |
|---|---|---|
| 全局 | `global` | 跨项目通用：偏好、平台约束、工具用法 |
| 项目 | `proj:<目录名>#<6位哈希>` | 仅在该工作区生效：项目结论、临时上下文 |

项目键来自 `session.header.cwd`（会话工作目录），哈希避免同名目录冲突。

### 四条规则

1. **捕获**：转录按会话的工作目录写入项目层；没有工作目录（如纯问答会话）写 `global`。
2. **画像**：注入"全局 + 当前项目"；当前项目未知时只注入全局——**宁可少注入，不跨项目泄漏**。未知 scope 不再回退到上一项目。
3. **检索**：项目视图 = 该项目 + 全局 + 历史无 scope 行；`scope='global'` 只看全局；`scope='all'` 只读、不过滤。写入 `scope='all'` 直接报错，避免把项目内容写进全局。
4. **界面**：面板提供「全部 / 全局 / 项目」三个筛选，并列显示两层计数。
5. **HTTP**：`/omni-memory/search` 裸请求默认 `global`；显式 `scope=proj:...` 才看项目层，客户端搜索自动带当前 scope。

### 不做的事

- 不自动把已有 `global` 笔记改判为项目级：归属是人的判断，迁移脚本无法可靠推断，误判比不分层更糟。
- 不按标签/关键词猜测项目：只认工作目录。
- 项目层不做物理隔离（同一 SQLite），过滤在查询层完成，保证全局层始终可见。

## 代价与局限

- 同一工作目录被多个会话使用时共享项目层（符合预期）；移动目录会生成新项目键，旧项目笔记需手动改 `scope`。
- 项目键可读性一般（`proj:memory-core#1a2b3c`），已在注入块与界面中展示，模型可以直接引用。
- 子代理（subagent）继承父会话工作目录时共享项目层，这是有意的。

## 验证

`test/scope-layers.test.mjs`（6 个用例）：

- 捕获自动落项目层，无工作目录落全局；
- 画像只含全局 + 当前项目，其他项目不泄漏；
- 项目检索包含全局、排除别的项目；`all` 不过滤；
- 列表路由按层过滤并报告两层计数。
