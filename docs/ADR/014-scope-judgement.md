# ADR-014：写入与检索的「归属判断」是确定性规则，不是猜

- 日期：2026-11-14
- 状态：已采纳

## 背景

分层上线后暴露出一个缺口：**层归属全凭调用方填写**。

- 我在写笔记时可能记成 `global`（该记项目的），也可能记成项目（该全局的）；
- 检索时如果不传 scope，就扫全部层，既慢又容易翻出别的项目内容。

用户要求"检索和记录要有一个判断机制"。

## 决策

### 写入判断：显式优先，其次看措辞，最后保守落到当前项目

```
显式 scope ？          → 用它（reason=explicit）
没有当前项目？          → global（reason=no-project）
含跨项目措辞且无项目痕迹 → global（reason=cross-project wording）
含项目痕迹             → 当前项目（reason=project-specific wording）
其余                   → 当前项目（reason=default-to-project）
```

- **跨项目措辞**：偏好/习惯/以后/总是/永远/一律/所有项目/跨项目/通用/铁律/禁止/不要再
- **项目痕迹**：本项目/这个项目/本仓库/本工程/本插件/src//docs//package.json/.mjs/.ts/.js/构建/部署/迁移/表结构/字段
- 结果里回传 `scope` 与 `scopeReason`，判断依据可见、可反驳。

**兜底为什么选项目层**：错了还可以在面板里看到并提升为全局；反过来，项目细节写进全局会出现在每个会话里，泄漏不好收回。

### 检索判断：有当前项目才用项目视图

- 有当前项目 → 搜「该项目 + 全局」；
- 没有当前项目 → 只搜全局（不再回退到上一项目，也不默认扫全库）；
- `scope=all` 是显式只读视图，可以看到全部层，但写入会被拒绝；
- 返回结果带 `scope` 字段，输出里也打印 `(scope proj:…)`，让人知道这次搜了哪层。

## 不做的事

- 不用模型**做默认**归属判断：默认离线规则可复现；需要更准时由用户显式打开 `OMNI_SCOPE_JUDGE=auto|always`（ADR-015），默认 `off` 不会把正文发给模型。
- 不做跨层自动去重：同一句话在两层是两条记录（scope 是身份的一部分），这条既有契约有测试保护。
- 不改写已有记录的 scope：归属是数据，不是视图。

## 验证

`test/scope-judge.test.mjs`（8 例）：

- 项目措辞 → 项目层；跨项目措辞 → 全局；含糊 → 项目；显式 → 显式；
- 无项目上下文 → 全局；
- 事实与笔记走同一判断；
- 检索默认按当前项目，`scope=all` 才跨层；
- 返回的 `scope` 与请求一致，便于追溯。
