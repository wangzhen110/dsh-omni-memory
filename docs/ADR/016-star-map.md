# ADR-016：星图用 Canvas 2D 手写 3D 投影，不引入图形库

- 日期：2026-11-14
- 状态：已采纳

## 背景

界面需要「可拖拽、可旋转」的记忆星图效果。

候选：

1. **three.js / pixi**：效果好，但客户端半边是单文件 `client.js`，由宿主直接加载，没有打包步骤。引入库要么走 CDN（离线/内网不可靠），要么塞进 `files` 里手工维护，都会破坏"插件零依赖"的约束。
2. **Canvas 2D + 手工投影**：自己算旋转矩阵与透视除法，节点数在几百级别时足够 60fps。

## 决策

用 **Canvas 2D** 实现，视觉参考开源程序化星系（4 旋臂、半径平方根分布、臂宽/厚度衰减、叠加发光、蓝→暖色）：

- **背景星**：1500 颗，按旋臂分布（`galaxyPoint`），三色带（暖/蓝）、闪烁、深度衰减、`globalCompositeOperation='lighter'` 叠加。
- **记忆星**：笔记=青色、实体=暖金色，三层同心圆做辉光，核心为白点；落在同一旋臂上，节点越多旋臂越亮。
- **星云**：两个径向渐变（紫/蓝）铺在底层，中心再叠一层暖色核心光。
- **连线**：事实关系用细线连接，透明度随景深变化。
- **交互**：`pointerdown/move/up` 旋转 + 惯性；`wheel` 缩放（0.45–2.8）；空闲 2.2 秒后自动旋转；悬停 16px 内显示标签。
- **分层**：顶部按 `scopes[]` 生成切换按钮，每层独立请求 `/omni-memory/graph?scope=…`；全局图与项目图数据互不混入。

数据来自 `/omni-memory/graph`：按 scope 从 `facts`/`notes` 构星与连线（不再是全局 entities 表），节点上限 220 实体 + 120 笔记。

## 代价与局限

- 没有真实 GPU 粒子与后处理 bloom，视觉是"接近"流行星系效果，不是真 3D 引擎。
- 1500 颗星 + 数百节点的每帧重绘在桌面端流畅；低端设备可能掉帧（未做降级开关）。
- 旋臂位置由索引哈希决定，同一记忆每次渲染位置稳定，但新增记忆会重新洗牌。**这是已知取舍**：稳定位置需要持久化布局，成本更高。
- 不支持触摸双指缩放（桌面端滚轮优先）。

## 代价与局限

- 没有真实光照与后期辉光，视觉是"近似炫酷"，不是 Three.js 级别。
- 节点超过约 300 后重叠会明显，所以接口按度数/重要性截断。
- 每帧都 `requestAnimationFrame` 重绘；面板隐藏时组件仍会占用一个 RAF 循环（DSH 面板切走后 DOM 移除，循环随之取消）。
- 不支持触摸双指缩放（桌面端滚轮优先）。

## 后续尝试（2026-11-15，已回滚）

曾把星图替换为**手写 WebGL2**（GLSL 点精灵 + 差速旋转 + bright-pass/blur bloom + 程序化星云，零依赖）。结果：

- 着色器编译通过、`webgl2` 上下文创建成功、离屏 FBO 尺寸正确（调试行 `gl 1859x460 dpr=1`，数据 `12/6200`）；
- 但画布在 **DSH 的 Electron 渲染进程里始终输出空白白屏**，无 GL 报错、无 JS 异常，`lastFrame` 无法落地。

结论：该渲染进程的 WebGL 合成不可用（或上下文被回收），盲调成本过高，已回滚到 Canvas 2D 版本。要真正达到 three.js 级效果，应先解决渲染进程 GL 输出（或离线打包 three.js 并在独立窗口渲染），而不是在组件里换 API。

## 验证

`test/graph-view.test.mjs`（5 例）：实体与边生成、笔记挂载、节点上限与无悬空连线、空库返回空图、仅 loopback。

真机：面板顶部常驻星图，可拖拽旋转、滚轮缩放，实际截图见交付记录。
