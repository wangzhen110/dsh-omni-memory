# ADR-011：增长治理用墓碑化保留上限；界面本地化用词典 + 订阅

- 日期：2026-11-14
- 状态：已采纳

## 背景

两件收尾事项：

1. 转录层只增不减，长期会撑大数据库；但 INV-04 规定「逻辑删除只写 `deleted_at`，不删行」。
2. 面板文案硬编码中文，DSH 支持多语言，界面应跟随当前语言。

## 决策

### 增长治理：`memory_compact`

- 输入：`keepChunks`（默认 5000，**下限 50**）、`apply`（默认 false）。
- 行为：统计活跃转录总数，超出保留上限的最旧记录按 `ts ASC, id ASC` **写 `deleted_at`**（墓碑），不执行 `DELETE`。
- 检索与 FTS 查询都已过滤 `deleted_at`，因此墓碑行立即退出召回，但仍可按 id 审计/恢复。
- 不自动运行：由调用方（人或定时任务）显式触发，避免后台任务偷改数据。

### 本地化：词典注册 + 订阅重渲染

- `ctx.locale.register(NS, 'zh'|'en', dict)` 注册两本词典。
- `ctx.locale.bind(NS)` 在渲染时取词；`ctx.locale.subscribe` 触发组件重渲染，避免文案冻结在挂载时的语言。
- 左栏入口的 `label` 用同一个 bind 返回，切换语言后菜单文字跟随。

## 代价

- 墓碑化的转录在导出/审计时需显式包含（默认查询过滤）。
- 词典目前只覆盖面板文案；工具描述仍是英文（模型面向，不需要本地化）。
- i18n 只做了中英两本，其他语言回退到键名。
