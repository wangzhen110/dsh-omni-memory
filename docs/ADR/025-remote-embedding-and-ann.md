# ADR-025：远程 embedding 加固与 ANN 的边界

- 状态：已采纳（v2.9.0）
- 日期：2026-11-17
- 关联：ADR-008（可插拔 embedding）、ADR-020（有界检索）、路线第 5 项

## 背景

ADR-020 把向量检索限制为"最近 5,000 条采样 + 词面候选补集"，解决了 1M 行的延迟；但还有两个问题：

1. **远程 provider 的工程细节**：批量上限、429 限流、超时重试都没有；
2. **ANN 缺失**：采样之外的老向量不会被语义召回。评审与路线都把它列为"未来"。

本轮做前者，并明确后者的取舍。

## 决策

### 1. Provider 预设与重试

- `OMNI_EMBED_PROVIDER` 预设（openai / dashscope / zhipu / siliconflow）填充默认 url/model；`OMNI_EMBED_URL` 仍可覆盖。
- `OMNI_EMBED_BATCH`（默认 64）：按批切分输入，避免超过 provider 的数组上限。
- `OMNI_EMBED_RETRIES`（默认 2）：429 与 5xx 按 250ms、750ms 退避重试；其它 4xx 不重试（坏 key/模型重试无意义）。
- 每次请求独立超时（`OMNI_EMBED_TIMEOUT_MS`）。
- 测试：预设解析、429 两次后成功、130 条按 64/64/2 切分；已有集成测试覆盖维度持久化、写入入队/flush、端点不可达降级。

### 2. 不做 ANN 的理由

评估过的选项：

| 方案 | 结论 |
|---|---|
| sqlite-vec / HNSW 原生扩展 | 需要额外原生依赖与多平台构建；插件是纯 JS 分发，引入即改变安装面 |
| 自研 LSH / IVF（纯 JS） | 可行，但需要索引表、重建流程与质量评估；当前没有标注集证明"比采样更好"，贸然上线会让召回不可预测 |
| 增加采样量 | 线性增加延迟；1M 全量向量读取是 GB 级，违背 ADR-020 的目标 |

**结论**：保持有界采样 + 词面补集；把 ANN 作为独立项目，前置条件是有标注集、有重建入口、有回滚方案。

### 3. 当前向量路线的能力边界

- 语义召回覆盖：最近 `OMNI_VECTOR_SAMPLE` 条向量 + 词面命中的旧向量；
- 完全无语义重叠、且不在最近采样内的旧记忆，**不会被向量召回**，只能靠词面命中；
- hashed 后端额外要求共享 token（ADR-020），remote 后端没有该限制。

这个边界写进 README 与 THREAT-MODEL 的权衡说明，不宣称"全库语义检索"。

## 验证

- `test/embed-provider.test.mjs` 3 例；`test/remote-embed.test.mjs` 3 例；
- 1M + 5 万向量基准：p95 56.4ms（ADR-020 记录）。

## 未来

- 真实商业 provider 的端到端验证（需要用户提供凭据与预算）；
- ANN 立项：标注集 → 索引原型 → 质量/延迟对比 → 迁移与回滚。
