# ADR-026：用户设定（性格 / 习惯 / 偏好）

- 状态：已采纳（v3.0.0）
- 日期：2026-11-17
- 关联：ADR-013（scope 分层）、ADR-012（自动召回）

## 背景

长期记忆解决的是"事实"，但用户的**风格与偏好**不是事实，也不该按证据校验：

- "回答直接、先给结论" 不是可验证结论，dream 会把它标成 `no_source`；
- "称呼用老王"、"偏好中文" 每次都要重复说；
- 项目层/全局层的事实隔离也不适合这些跨项目恒定的设定。

需要一个独立的、可编辑、始终注入的设定层。

## 决策

### 1. 独立存储（Schema v10）

```sql
CREATE TABLE persona (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER);
```

- 与 notes/facts 分开：不参与检索排序、不参与 dream 校验、不进审计历史；
- 字段名任意（默认建议：称呼、性格、习惯、偏好、其他）；
- 单个值 ≤1200 字，总数 ≤4000 字；空值即删除。

### 2. 注入

在 `omni-memory` prompt section 的最前面注入：

```
用户长期设定（来自面板，高于临时指令）：
- 称呼：老王
- 性格：直接、先给结论
```

- 位置在长期记忆之前，明确"高于临时指令"；
- 计入同一 1200 字画像预算（超长时优先保留设定，因为它是用户显式配置）。

### 3. 编辑入口

- 面板工具条新增「设定」按钮：模态表单（称呼 / 性格 / 习惯 / 偏好 / 其他），保存即写入；
- 工具 `memory_persona({ action: 'get' | 'set', values })`；
- HTTP `GET/POST /omni-memory/persona`：写操作 POST + CSRF + 同源，参数放查询串（宿主可能读空 body）。

### 4. 自动提炼（v3.1.0 修订）

设定不应由用户逐条填写，而应从日常记忆中生长出来：

- **证据**：活跃事实（按 confidence/时间取前 80）+ 高重要度未争议笔记（前 40）；
- **规则层**：事实关系（称呼/喜欢/习惯/性格）与笔记句式（"叫我…"、"回答风格：…"、"喜欢…"），离线可解释；
- **模型层**：宿主有 `llm` 时用小模型输出 JSON，失败回退规则；提示词明确"只能用记录里的事实"；
- **频率**：每 20 次相关写入且距上次 ≥1 小时，后台刷新，不阻塞写入；
- **人工修正**：面板可改字段，保存即覆盖；「重新提炼」按钮可手动触发。

### 5. 不做的事

- 不做按项目覆盖（设定是跨项目恒定的；项目差异用记忆/提示表达）；
- 不做版本历史（这是配置，不是知识；需要时用导出备份）；
- 不做模型自动生成（用户显式写，避免"AI 给自己立人设"）。

## 残余风险

1. 设定会进入每一轮系统提示，超长会挤占画像预算（已限制 4000 字）；
2. 全局设定对所有项目生效，项目级偏好仍需在对话中表达；
3. 与 `memory_write` 的"性格"类笔记可能重复，后者仍会被 dream 标记 `no_source`。

## 验证

- `test/persona.test.mjs` 5 例：工具读写、超长拒绝、HTTP CSRF、注入、清空移除；
- `test/persona-auto.test.mjs` 3 例：规则提炼、宿主模型提炼、refresh 路由鉴权；
- 真机：设置后 GET 回读、面板按钮渲染（截图受前台窗口限制，见 ADR-017 的同类说明）。
