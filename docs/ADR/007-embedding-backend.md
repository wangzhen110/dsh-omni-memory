# ADR-007：默认向量后端用哈希字符 n-gram，而不是 transformer 模型

- 日期：2026-11-14
- 状态：已采纳（可替换）

## 背景

M2 需要「向量路线」参与混合检索。理想实现是本地语义嵌入（bge-m3 ONNX，~500 MB）+ 近似最近邻。但本插件的第一约束是**零依赖、可安全加载**：宿主不能假设用户装了 onnxruntime、也不该在插件激活时触发大文件下载。

## 决策

默认后端为**哈希字符 n-gram 词频向量**（512 维，L2 归一化）：
- 中文切二元组、拉丁/数字保持整词；
- 每个 token 用 FNV-1a 哈希到某一维，符号由哈希高位决定；
- 权重为 `1 + log(tf)`，向量归一化后余弦 = 点积。

检索时与词面路线做 **RRF（k=60）** 融合；另加两条防噪声约束：
1. 余弦阈值 0.2；
2. 至少共享一个 token，否则不入选。

## 实测（黄金集 20 条语料 / 24 个问题）

| 指标 | 仅词面 | 词面 + 向量 | 变化 |
|---|---|---|---|
| recall@10 | 1.000 | 1.000 | 0 |
| MRR | 0.770 | **0.917** | **+0.147** |

延迟（10,000 行、40 次查询）：p50 5.5ms / p95 12.6ms。

## 诚实的局限

- 这**不是语义模型**：换说法但不共享任何字的查询，它一样召回不到。
- 因此 FR-17「语义近似」**未完全满足**，只满足「排序融合」；真语义列为 FR-21。
- 换说法能力要靠外部 embedding 后端（OpenAI 兼容 `/embeddings`）替换 `embedText`。

## 代价与迁移

- 维度从 256 提到 512 时用迁移 v4 清空并重建派生索引（向量是派生数据，重建安全）。
- 未来接入真嵌入：新增后端实现 + 一次全量重建，接口不变。
