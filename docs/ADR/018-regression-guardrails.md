# ADR-018：用机械护栏防止同类问题复发

- 状态：已采纳
- 日期：2026-11-17
- 关联：ADR-017、v2.3.1/v2.3.2 两轮外部评审

## 背景

两轮评审暴露的问题有共同形状：**实现按功能路径写，测试按同一套假设写，文档按设计意图写，三者之间没人强制对齐。**

具体表现：旧状态（superseded / valid_to）在 7 个读路径中漏了 5 个；scope 用全局"最近一次"兜底；HTTP 把 loopback 当认证；远程维度只存在内存里；README 的用例数、路由数、ADR 数长期漂移。这些问题不是单点笔误，而是**缺少让"不一致"暴露的机制**。

## 决策

引入四类护栏，且全部可执行、可失败、可审计：

### 1. 状态×读取路径矩阵测试（`test/lifecycle.test.mjs`）

- 构造 active / superseded / tombstoned / contested / expired 的行，分布在 global、项目 A、项目 B 三层；
- 对 **search / profile / graph / node / list / re-read chunk** 逐条断言"只返回该返回的"；
- 该文件在首次编写时就抓到真实漏洞：`/omni-memory/list` 当时仍返回被替代笔记（已修复，并新增 `?audit=1` 审计视图保留历史可见性）。

规则：**新增任何读路径（路由、查询函数、注入块）都必须往这个矩阵里加一行**；只有活跃状态可以被默认读取，历史状态只能通过显式审计参数读取。

### 2. 文档一致性门禁（`scripts/check-docs.mjs`，并入 `npm run check`）

从代码与文件系统**实测**以下数字，再与文档互相核对：

- 版本（package.json ↔ DESIGN ↔ CHANGELOG）
- 用例数（统计 `test()` ↔ README 徽章/正文 ↔ DESIGN NFR）
- 工具数（注册的 `memory_*` ↔ README 表格）
- 路由数（注册的 `/omni-memory/*` ↔ DESIGN 架构行）
- ADR 数量（文件数 ↔ README）

任一不一致 → `npm run check` 失败 → 不能发布。

### 3. 威胁模型前置（`docs/THREAT-MODEL.md`）

- 资产、参与者、信任边界、现有控制、残余风险、新增路由清单、复查触发条件；
- 明确写着"loopback 不是认证""数据库明文""memory poisoning 未完全解决"——避免再次出现 README 过度承诺；
- 新路由/新外部调用必须先更新此文件。

### 4. 外部补丁接收流程

对任何外部提供的补丁（评审、协作者、AI）：

1. **核对声称文件与补丁实际内容**（本轮评审声称有 `test/fixes.test.mjs` 与 ADR-017，补丁里两者都不存在）；
2. 在**隔离分支**应用（`git switch -c review/...`），不在工作区直接打；
3. 用 `patch -p1 --dry-run` 记录命中情况，再用 `patch -p1 -f` 应用；
4. 通读全部 hunk，不只看新增功能；
5. **独立补测试与探针**（不沿用补丁自证），真实库副本跑迁移；
6. 真机安装 + 路由/面板/写入 scope 冒烟；
7. 发布前跑 `npm run check`（含文档门禁）与全量测试。

### 5. CI

`.github/workflows/ci.yml`：每次 push / PR 在 Node 24 上执行 `npm run check` 与 `npm test`，红灯不合并。

## 结果

- 170 / 170 用例通过（含 7 条生命周期矩阵）；
- 文档门禁一次通过前，实际抓出 4 处漂移（版本、用例数、ADR 数、路由描述）；
- 矩阵测试抓出 1 个真实泄漏并修复。

## 未来

- 状态矩阵应扩展到"并发写入"与"重启恢复"两个维度（目前是单进程顺序场景）；
- 性能门禁（10k/100k p95）尚未进入 CI，1M 仅作记录；
- 数据模型类问题（多值关系、实体消歧）不能用矩阵测试解决，需要单独立项与迁移设计。
